[ 2026/07/08 ]
---------------------------------------------------------------
- Object sprites are now placed with the room's own classic-to-HD
  transform instead of the fixed 6.0 x 7.2 scale. The Y scale is
  the SE room height over the classic RMHD height: every SE room
  is 1037 px tall, but the usual game rooms show 144 classic lines
  (1037/144 = 7.2014) while fullscreen rooms - the island maps
  (monkey-1..5, melee, map), close-ups (cu-brush, cu-naviga,
  cu-works), copy protection, logo - show all 200 lines and scale
  by only 1037/200 = 5.185. The X scale is the Y scale divided by
  the 1.2 VGA pixel aspect (6.0012 / 4.3208), and the classic 4:3
  view is centered horizontally in the room: scrolling rooms are
  authored exactly as wide as the classic art, but fullscreen
  rooms carry ~268 px of extra widescreen scenery on each side.
  Previously the dry river bed in monkey-3 hung off the bottom of
  the map ~80 px left of the painted river bed; it (and monkey-4's
  river/pond, cu-naviga's eyes, copycrap's dial) now sit
  pixel-exact on the background art, verified by template-matching
  the retail textures. The calibration overlay and actor origins
  honor the new origin shift, and the room spritesheet editor
  seeds its HD Scale fields (now 4 decimals) with the room's own
  scale, recomputing the centering as they are edited
- Fixed the transparency checkerboard in the texture/room/costume
  views turning black or grey after scrolling: the partial repaint
  only filled the grid up to the clip's width/height instead of its
  right/bottom edge, and the pattern was keyed to the clip origin
  instead of the control origin
- The program has been a sprite editor rather than an XML parser
  for a while, so it is now named one throughout. The executable
  is MonkeyIslandSpecialEditionSpriteEditor.exe, renamed from
  MonkeyIsland1SpecialEditionXmlParser.exe: update any shortcuts
  pointing at the old name. Everything else is unchanged, and
  UserSettings.xml still sits beside the executable, so recent
  files and window positions carry over
- The solution and both projects moved to the SDK-style csproj
  format, still targeting .NET Framework 4.8.1. The unit tests can
  now be discovered by `dotnet test` and run on every push. Note
  that building from Visual Studio now needs the ".NET desktop
  development" workload installed, as SDK-style projects do not
  build without it

[ 2026/07/07 ]
---------------------------------------------------------------
- Room viewer now shows costume actors (e.g. the pirate leaders in
  the bar) at the positions the game places them. The classic SCUMM
  scripts are scanned with a new SCUMM v5 bytecode decoder (all 721
  retail scripts decode byte-exactly) for putActorInRoom/putActor
  opcodes with literal arguments, together with the costume, facing
  direction and elevation the same script sets up. Each placement
  gets a checkbox in a new "Actors" list; the first placement per
  actor (the room's initial setup) starts visible, later ones
  (mostly cutscene positions) start hidden. Actors draw above the
  object sprites and below the static foreground, like the game.
  Placements whose coordinates are computed at runtime from
  variables cannot be extracted statically and are not shown
- Actor sprites are anchored bottom-center to the classic costume
  cel they replace, matching the game, instead of using the SE
  sprite's own ScreenX/ScreenY relative to the actor. The two agree
  for most costumes, but several (leaders, lechuck, school-of-fish,
  birds) carry SE offsets up to ~30 classic pixels off; the pirate
  leaders sank behind their table (only the hats showed) until the
  classic anchoring put their faces above it, as in-game
- Actors draw in front of or behind the static foreground depending
  on the mask (z-plane) of the nearest classic walkbox (BOXD, newly
  parsed), like the game: the pirate leaders sit on an unmasked box,
  so their hands and mugs rest on the table (the occlusion is drawn
  into the costume art), while the cook, the storekeeper and the
  fortune teller stand on masked boxes and stay behind their
  table/counter foregrounds
- Room preview now composites like the game: only the first static
  sprite layer is the background; further static layers (tables,
  door frames) are drawn as a foreground above the object sprites.
  Previously all static layers were flattened under the sprites,
  so sprite regions the game hides behind the foreground showed
  through - e.g. the bar (room 28) kitchen door looked ~150 px too
  far right because its sprites keep the classic door position
  while the SE background art moved the painted door left, with the
  foreground layer masking the difference in-game
- Added a "Show foreground layer" toggle to the room spritesheet
  editor for editing sprites the foreground covers

[ 2026/07/06 ]
---------------------------------------------------------------
- Decoded the "unknown" costume fields and renamed them: sprite
  MoveX/MoveY (floats, HD-scaled classic move deltas) and
  PathPointIndex; frame Command and SoundName (frames can trigger
  sounds via a shared name string at the end of the file, which the
  old parser dropped); sprite group FirstSpriteIdentifier (frame
  sprite ids are relative to it - fixes wrong/missing sprites in
  costumes like seaweed and little-jojo); track PlaybackFlags;
  path point Type/Flag/X/Y; header PathPointTypeCount and the
  0.25/1.0/1.0 floats
- Fixed costume parsing (path point lists whose size is a multiple
  of 16 no longer corrupt the texture file names) and rewrote the
  costume packer to reproduce the original layout: all 122 costumes
  in the retail pak now repack byte-identically (previously none did)
- Added classic SCUMM costume parsing (COST resources + the DCOS
  directory) - limbs and cels with their relX/relY/moveX/moveY,
  matched to SE sprite groups/sprites for calibration
- Added Costume Spritesheet Editor (right-click a costume / File
  menu in the costume viewer): animation preview with playback and
  per-frame stepping, atlas view with drag/arrow-key nudging,
  numeric editing of texture rect, screen position and move deltas,
  classic-cel overlay with per-sprite delta readout and an
  "Align to classic position" button to fix mis-aligned sprites
- Added "Save override" for costumes: writes the loose override
  binary the game loads plus the overrides XML export
- Costume texture PNG export/import (same override mechanism as
  the room editor)
- Costume viewer and editor now respect loose override files
- Replaced the bundled DevIL.NET2 wrapper and native DevIL DLLs
  (DevIL.dll/ILU.dll/ILUT.dll) with the managed Pfim NuGet package
  for decoding DXT textures; no native runtime is shipped anymore
